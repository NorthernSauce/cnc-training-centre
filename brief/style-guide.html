A.04

Grid + breakpoints

Container width 1280 px max. Page edge padding fluid via clamp(1.25rem, 3vw, 2.5rem). Section block padding fluid via clamp(2.5rem, 5vw, 5rem). Long-form prose capped at 65 ch. Editorial layouts are asymmetric — break the grid intentionally for emphasis.

article-row, form-grid-2
900 pxDesktop · asymmetric splits

--ns-max-content

Container queries (@container) handle component-level responsiveness where a card or block needs to adapt to a sidebar's width rather than the viewport. Viewport queries handle page layout only.

A.05

Radius

Engineering-precise. Small radii only. Pills are the single exception — reserved for tags + filter chips, never any other element.

None · 0 pxbuttons, callouts, headers, marginalia headers
Tight · 2 pxcards, panels, form inputs, alerts
Soft · 4 pxoccasional softening, badges, secondary chips
Pill · 999 pxtags + filter chips only
A.06

Shadow + depth

No drop shadows. Direction A — The Engineering Manual relies on rules, borders, and surface alternation to define depth. Decorative drop shadows are an AI-design fingerprint and are banned across the project.

  • Hierarchy via 1 px hairline rules + 2 px ink rules at panel openings.
  • Surface tier (paper / paper-tint / paper-deep / anchor) creates implicit depth without shadow.
  • The single permitted "lift" is the 1 px translateY on card and primary-button hover — a feedback signal, not a depth signal.
  • Focus rings use a soft 3 px box-shadow tinted from the focus colour. This is functional, not decorative.
A.07

Motion

Restraint. Motion intensity capped at 6/10. Use motion for state change only — never for decoration. Reduced-motion users get the end state with no transition.

Durations

--ns-dur-fast
120 ms · hover state, button arrow nudge, link underline
--ns-dur-base
200 ms · panel transitions, accordion open/close
--ns-dur-slow
320 ms · page-section reveal, hero entrance

Easings

--ns-ease-out (out-quart)
Default for entrances, hovers, anything decelerating into rest.
--ns-ease-in-out
Symmetric transitions (open/close).

Rules

  • Animate transform and opacity only. Never width, height, padding, margin.
  • Height changes use grid-template-rows transitions, not height directly.
  • No bounce or elastic easing. Real objects decelerate smoothly.
  • No perpetual animation. If it loops, it earned its place — otherwise remove.
  • prefers-reduced-motion: reduce zeros out every duration via the tokens cascade.

B.09

Container widths

Three modes — page-edge, content, prose. Hero elements may break full-bleed when imagery / motif demands it.

  • Page edge — padding-inline: clamp(1.25rem, 3vw, 2.5rem). Default outer padding for everything except full-bleed sections.
  • Content width — max-width: var(--ns-max-content) (1280 px). Used for the main .wrap container.
  • Prose width — max-width: 65ch. Long-form body cap (Hub articles, About copy). Anything wider is fatiguing.
  • Full-bleed — allowed for hero technical-drawing motifs, anchor-tier footers, mark/highlight surfaces. Default to contained.
B.10

Section rhythm

Pages alternate surface tier to create visual rhythm. Default sequence on long pages: paper → paper-tint → paper → anchor. Never two adjacent sections on the same tier without an explicit rule divider between them.

Paper · default
Paper Tint · secondary
Paper Deep · inset
Anchor · contrast

The anchor tier appears at most once per page — typically the footer or a high-contrast CTA band. Overuse erodes its impact.

D.23

Image treatment

Photography is non-load-bearing on Direction A. Type and technical-drawing motifs do the visual work. When photography is used, it's a tightly-cropped fragment of real equipment — never a smiling engineer with a laptop, never generic stock.

Open · Photography

Client has no usable people / classroom / teaching photography at brief sign-off. Workshop fragment shots (control panels, tool magazines, chip evacuation, fixturing) are the only photography category planned at launch. A proper shoot of David teaching is deferred to a post-launch swap-in.

Photography rules

  • Tightly cropped, never the whole machine — the fragment carries more authority than the wide shot.
  • Real CNC equipment only. Tool magazines, control panels, chip evacuation, real fixturing.
  • Captions in --ns-text-tiny uppercase tracking, identifying the machine + control where relevant.
  • No filter / duotone / saturation effects. Real shop colour, lit honestly.
  • No people-with-laptop shots, no high-vis-vest stock, no smiling engineer hands clasped.

E.26

Responsive behaviour

Mobile-first. Components flex from 375 → 1440 px. Never hide critical functionality on mobile — adapt the interface, don't amputate it.

  • Hero — single column on mobile, asymmetric 1.5fr/1fr split at 900 px+.
  • Marginalia — folds beneath the body column on mobile; sits to the right at 900 px+. Always full-width within its container.
  • Article rows — single column on mobile; max-content / 1fr / max-content at 700 px+ (number / title+meta / arrow).
  • Card grid — auto-fit, minmax(260px, 1fr). Breakpoint-free.
  • Form two-column — single column under 600 px; two columns at 600 px+.
  • Spec block — 2 columns under 700 px; 3 columns at 700 px+.
  • Navigation — horizontal bar on desktop (designed in phase 4); real menu toggle + stacked panels on mobile.
  • Type — headings clamp continuously; body / UI text steps at fixed sizes (no fluid body type — fluid type creates accessibility friction in product UI).
E.27

Print stylesheet

Buyers print enquiry confirmations, course details, and About / capability sheets. Print stylesheet ships with the theme — basic, functional, ink-saving.

  • Hide nav, hide footer mark-up that's pure ornament, hide ads / CTAs.
  • Force --ns-color-paper = white, --ns-color-ink = near-black for crisp print.
  • Strip surface tints — Paper-tint / Paper-deep / Anchor render as white with hairline borders only.
  • Body type at 11 pt, headings step down one size from screen.
  • Show full URL after inline links (a::after { content: " (" attr(href) ")"; }).
  • Page breaks: avoid breaking inside marginalia, spec blocks, pull-quotes.
F.28

Microcopy rules

UI copy follows the Northern Sauce humaniser standard. Chrome (nav, footer, error pages) stays neutral and professional — voice lives in long-form. Buttons, labels, placeholders, and error messages are specific, plain, and human.

  • Buttons. Specific verbs over generic ones. "Contact David" not "Submit". "Browse the Hub" not "Learn more". "Apply for this course" not "Get started".
  • Form labels. Short, capitalised first word only, no colons. "Your name", "Company (optional)", "Which machines or controls?"
  • Placeholders. Specific real-world examples, not generic. "07700 900 000" not "Phone". "Mazak Integrex i200 + Hurco VM10" not "Enter machine model".
  • Error messages. What went wrong + what to do. "Please tell us your name so we can reply" not "Required field". "We couldn't send your enquiry — try again or call 07834 858 407" not "Error".
  • Capitalisation. Sentence case throughout. Title Case is reserved for proper nouns (Fanuc, Mazak, Edgecam).
  • Numbers. Always digits in UI. "5 working days", not "five working days". Use thousands separators. £ prefix, no decimal on whole pounds (£700, not £700.00).
  • Banned phrases. "Submit your enquiry today!", "Click here", "Learn more", "Get started", "Read more". Each is a missed opportunity for specificity.
G.29

Logo usage

CNC Training Centre wordmark. Used in nav (top-left), footer, and any official PDF / email signature. Clearspace = the height of the wordmark on all sides. Minimum print size 25 mm wide. Never recolour.

Open · Logo asset

Existing logo is to be carried through. Asset file (SVG + transparent PNG, on-light + on-dark variants) to be supplied by the client. If the existing logo needs a light refresh — colour swap to refined brand-blue, stroke clean-up — that decision is deferred to phase 4 with Dave.

Rules

  • Clearspace = 1× wordmark cap-height on all four sides.
  • Minimum digital size: 120 px wide.
  • Minimum print size: 25 mm wide.
  • On-light: full-colour wordmark over paper / paper-tint surfaces.
  • On-dark: inverse wordmark over anchor surfaces (footer).
  • Never recolour outside the approved set. Never apply effects (drop shadow, glow, gradient).
  • Never letter-space or stretch.
G.30

Visual signature

The two distinctive design moves that make Direction A — The Engineering Manual instantly recognisable as CNC Training Centre. Applied with restraint; if everywhere, they stop being signature.

The marginalia rail.

Service pages and long-form Hub articles carry a structured sidebar with machine / control / spec / quick-fact callouts. The page edge does work — it reads as the margin of a technical paper, not the empty space of a marketing site.

The dimension-callout rule-cap.

Section openings and closings use a thin rule with end-ticks and a small uppercase label. Mimics the dimension callouts on a workshop drawing. Used sparingly — section breaks only, never as section dividers within a single section.

Supporting motifs: numbered section headers (§02.04), tabular numerics on spec blocks, em-dash bullets. These reinforce the manual aesthetic without becoming load-bearing signatures.

H.31

Accessibility

WCAG 2.1 AA across the project. Every palette pairing tested for contrast; every interactive element has a visible focus state; reduced-motion respected; alt text rule documented below.

  • Contrast. Body text (Ink on Paper) passes AAA; secondary (Ink-soft on Paper) passes AA Large; placeholder (Ink-faint) is non-functional text only.
  • Focus states. Every interactive element renders a 2 px outline in Focus colour, offset 2 px. Visible on every tier (paper, tint, deep, anchor).
  • Keyboard navigation. Tab order matches reading order. Skip-to-content link as the first nav item. Mega menus open on click, never hover-only.
  • Alt text. Photography: describe the equipment, not the aesthetic ("Mazak Integrex i200 control panel, soft chuck mid-cycle"). Decorative motifs: alt="" with role="presentation". Icons inline with text: aria-hidden="true" if the adjacent text already describes the action.
  • Reduced motion. All durations zero out under prefers-reduced-motion: reduce. No essential information conveyed by motion alone.
  • Semantic HTML. Real <button> for actions, real <a href> for navigation. Headings nested in order. Landmarks on every page (header, nav, main, footer).
  • Form labels. Every input has an associated <label>. Error messages linked via aria-describedby. aria-invalid="true" on fields in error.
H.32

Performance

Two-font web project, no hero video, minimal photography. Targets: LCP under 2.5 s on 4G, CLS < 0.1, total page weight under 600 KB for a typical Hub article.

  • Fonts. Tanker + Synonym via Fontshare CDN. display=swap. preconnect to api.fontshare.com. Two faces, six weights total.
  • Images. WebP only. Workshop fragments under 80 KB at 2x. Hub article in-line images under 60 KB. No autoplay video. YouTube embeds lazy-loaded with a thumbnail-first pattern.
  • JavaScript. Zero at first paint for static pages. Hub filter, mega menu, mobile drawer are progressive enhancements only. No framework.
  • CSS. tokens.css + components.css ship as critical inline at build time. Tailwind utilities layered on top for page assembly (phase 5).
  • Forbidden. Hero autoplay video. Heavy JS-driven scroll animation. Third-party chat widgets. Pixel trackers from anything other than analytics. Web-font fallback flashes longer than 100 ms.
I.33

The closed system — Do / Don't

The hard rules that bind every later phase. Phase 4 designers, phase 5 developers, future content writers: this is the contract.

Do

  • Use tokens for every colour, type size, spacing, radius, and motion value — no hard-coded values.
  • Name actual machines, controls, problems in body copy. Specificity is the proof.
  • Use the marginalia rail for spec / control / quick-fact callouts on service pages and long Hub articles.
  • Use rule-cap dividers at section openings and closings, sparingly.
  • Cap body line length at 65 ch. Wider is fatiguing.
  • Reach for type, rule, and surface tier before reaching for a card or container.
  • Reserve green for video-content tags only.
  • Make focus states visible on every surface.
  • Use gap for sibling spacing, never margin.
  • Animate transform + opacity only. Use ease-out cubics. Honour reduced-motion.

Don't

  • Use the reflex font set — Inter, Roboto, DM Sans, Plus Jakarta, Fraunces, Newsreader, Lora, Crimson, Playfair, Cormorant, IBM Plex, Space Mono, Space Grotesk, Outfit, Instrument *, Syne.
  • Use gradient text. Anywhere. Ever.
  • Use border-left accent stripes wider than 1 px on cards, list items, callouts.
  • Use cyan-on-dark or purple-to-blue palettes.
  • Use identical 3-card icon grids stacked section after section.
  • Centre everything. Asymmetric editorial layouts are the default.
  • Use the hero metric template (big number / small label / supporting stat / gradient accent).
  • Use glassmorphism, decorative drop shadows, or neon accents.
  • Use generic stock photography. People-with-laptop is an automatic fail.
  • Add a second brand colour. Green is reserved for video tags, nothing else.
  • Write voice into chrome (nav, footer, error pages). Voice lives in long-form only.
  • Animate width, height, padding, or margin. Transform + opacity only.
